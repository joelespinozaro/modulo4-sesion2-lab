01

Un asistente que ya funciona, ahora frente a alumnos reales

El problema · Contexto

El instituto ya tiene un asistente que responde sobre programas, precios, horarios y matrícula con RAG. Funcionaba en un notebook. El repo resuelve la siguiente pregunta: ¿qué hace falta para que cientos de alumnos le escriban por WhatsApp sin que se rompa, se filtre un dato personal o se dispare el costo?

Canal

Llegar por WhatsApp

Los alumnos no abren una web: escriben por WhatsApp. Hace falta un puente entre WhatsApp y el agente.

Contexto

No saturar el prompt

Cada área (IA, ciberseguridad, desarrollo, UX) tiene sus reglas. Si todas viajan en cada mensaje, sube el costo y baja la precisión.

Control

Saber qué pasó

Cuánto tardó, cuántos tokens usó, si el proveedor falló y si hubo que reintentar.

Seguridad

Bloquear ataques y cuidar datos

Alguien intentará cambiar las reglas del agente. Otro pegará su DNI o una API key.

Calidad

Detectar regresiones

Un cambio en una regla de seguridad no puede llegar a producción sin una prueba que lo confirme.

Producción

Desplegar y medir

Opcional: llevarlo a la nube, con un servicio gestionado de seguridad y evaluación continua.

La idea central

Ninguno de estos problemas se arregla con un modelo más grande. Se arreglan con ingeniería alrededor del modelo: canales, middlewares, guardrails y pruebas. Por eso el repo crece por capas, una por rama.

02

Tres servicios propios, un contenedor y dos bases de datos

Arquitectura · Contexto

El sistema tiene tres servicios que escribes o modificas tú (Gateway, Agent API y, desde la parte 4, el MCP server), un contenedor que no tocas (WAHA) y dos bases de datos que ya conoces de la sesión de RAG. Elige una rama para ver qué se enciende.

03

Cada carpeta es un servicio, y cada servicio tiene la misma forma

Mapa de carpetas · El código

Los tres servicios siguen el mismo patrón por capas: routes recibe la petición, controllers la valida, services tiene la lógica y repositories habla con la base de datos. Si entiendes una carpeta, entiendes las tres.

Dónde mirar primero

Casi todo lo de esta sesión pasa en un archivo: 02_agent_api/src/services/agent_service.py. Ahí se arma el agente con create_agent y se le pasa la lista de middlewares. Compara ese archivo entre ramas y verás la sesión entera.

06

Qué necesitas antes de la clase y en qué orden se levanta

Puesta en marcha · Manos a la obra

El orden importa: cada servicio necesita que el anterior esté arriba. Los comandos completos para Linux, macOS y Windows están en el laboratorio guiado de la guía de la sesión.

Antes de clase

Requisitos

Python 3.11 o superior, Docker, Git, una API key de OpenAI, PostgreSQL y Qdrant con los documentos del instituto (o la carpeta 01_data_setup), un número de WhatsApp de pruebas y, para la parte 4, una API key gratis de Groq.

En clase

Orden de arranque

1. WAHA en Docker. 2. Agent API en :8080. 3. Gateway en :8090. 4. En el dashboard de WAHA: sesión, QR y webhook. 5. Un mensaje desde otro celular.

Archivo .envVariables que tienes que completarDesde
02_agent_api/.envOPENAI_API_KEY, DATABASE_URL, QDRANT_URL, QDRANT_API_KEYParte 1
02_agent_api/.envTOKEN_BUDGET (8000 por defecto)Parte 3
02_agent_api/.envDEMO_MCP_SERVER_PATH (ruta absoluta a 03_mcp_server/mcp_server.py), GROQ_API_KEYParte 4
02_chatbot_gateway/.envCHATBOT_API_URL, WAHA_API_URL, WAHA_API_KEYParte 1
03_mcp_server/.envOPENAI_API_KEY y las de QdrantParte 4
Seguridad

Los .env nunca se suben: el .gitignore del repo ya los excluye. Si alguna vez subes una key por error, no basta con borrarla del archivo: queda en el historial de git. Hay que revocarla y crear otra.

08

Lo que entregas al final de la sesión

Entregable · Cierre

Un agente production-ready con skills modulares, hooks de seguridad, test suite y evaluación continua. En concreto:

Evidencia 1

Conversación por WhatsApp

Captura de una pregunta respondida con información del instituto.

Evidencia 2

Una skill propia

Una carpeta nueva en 03_mcp_server/skills/ con su SKILL.md, y el log donde se carga.

Evidencia 3

Un ataque bloqueado

El log con la capa que lo detuvo y el hash del mensaje.

Evidencia 4

Tests en verde, más uno tuyo

pytest tests/guardrails -q pasando, con un test nuevo escrito por ti.

Cómo se revisa

No gana el agente con más capas. Gana quien explica por qué cada hook está en ese orden y qué pasaría si se quita.
